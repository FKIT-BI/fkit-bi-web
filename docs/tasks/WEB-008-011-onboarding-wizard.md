# WEB-008…011 — мастер «Подключить машину»

Спецификация: `fkit-bi-infra/docs/bmad/implementation-artifacts/spec-web-onboarding-wizard.md` (разделы 4–5).

## Scope

**WEB-008. Шаблоны сигналов** — `src/features/onboarding/templates.ts`: 12 шаблонов («Машина в работе», «Авария»,
«Скорость», «Температура», «Счётчик продукции»…) и «Свой сигнал», наборы по типу машины, подбор единицы из справочника
по `quantityCode`. Справочник единиц переведён (`UNIT`, `unitLabel`): backend отдаёт названия и символы по-английски
(`Piece`, `pcs`, `rpm`). Помощники единиц перенесены в `src/shared/lib/units.ts`; мониторинг показывает символ вместо кода.

**WEB-009. Конструктор правил** — `src/features/state-rules/`: модель (ответы на вопросы ↔ правила, плоские условия,
текстовое описание, клиентская проверка) и `StateRulesEditor` с вкладками «Вопросы» / «Подробно» / «JSON для экспертов».
«Подробно» — карточки правил: сигнал, оператор по формату значения, значение (да/нет, число, диапазон, список, допуск
для дробного «равно»), «все условия / любое из», своё условие выхода, задержки, порядок = важность. Сложные условия (NOT,
вложенность) редактируются в JSON. Ошибки `validate` показываются у своего правила. Заменил JSON во вкладке «Правила
состояний» карточки машины; `suggestRules` удалён (его заменил `suggestAnswers`).

**WEB-010. Мастер** — `src/features/onboarding/`: семь шагов (предприятие → смены и причины → линия → машина → сигналы →
состояние → запуск), каждый сохраняется на сервере по «Сохранить и далее» (`actions.ts`). Возврат назад обновляет уже
созданное, убранный сохранённый сигнал отключается, при конфликте автокода — повтор с суффиксом. Черновик в
`sessionStorage` (`fkit-bi-onboarding-draft`), панель «Что это?», шаблоны смен и типовой справочник причин
(`presets.ts`), итог с проверкой готовности и экран успеха: «Сгенерировать тестовые данные», «Подключить ещё машину на эту
линию», «Открыть мониторинг».

**WEB-011. Встраивание** — вкладка «Подключить машину» первая, «Настройка» переименована в «Готовность» и открывается по
умолчанию, на пустом стенде сразу открывается мастер. «Продолжить настройку» в чек-листе и в списке машин открывает
мастер на первом незавершённом шаге по данным сервера (`draftForMachine`). Копирование набора сигналов, узлов и правил с
другой машины (`copyFromMachine` + `mapRules`). Старый `EquipmentSetup.tsx` удалён.

## Verification

- `npm test` — 105 тестов: сквозной тест мастера на моках (от выбора предприятия до подключённой машины, затем «ещё
  машину»), копирование с машины-образца, модель и редактор правил, продолжение настройки из чек-листа.
- `npm run typecheck`, `npm run lint`, `npm run build`.
- Мок-режим в браузере: мастер пройден целиком — новая линия, «Экструдер ЭК-3» с типом «Экструдер», «Добавить все»
  (5 сигналов), предложенные правила, «Всё готово к подключению», машина подключена.

## Ограничения

- Причины потерь добавляются только если у предприятия справочник пуст; смены — только если нет активных смен.
- Линию уже созданной машины мастер не меняет (подсказка ведёт в «Линии и машины»).
- `DISABLED` машины по-прежнему всегда «Не подключена» (см. WEB-006).
